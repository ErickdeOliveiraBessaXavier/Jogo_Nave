# Revisão dos Ajustes — Spawner + Levels

## Context

O usuário aplicou ajustes após análise de bugs e melhorias no sistema procedural e de inimigos por tema.
Este plano documenta o resultado da revisão do commit HEAD~1 (`levels.py`) e aponta o que foi feito
corretamente, o que introduziu novos problemas, e o que ainda precisa ser corrigido.

---

## O que foi feito corretamente

### 1. `_apply_theme_enemy_rules` agora aceita `difficulty_preset`
Antes a assinatura não aceitava o parâmetro, mas era chamada de 4 lugares que precisavam passá-lo.
O usuário corrigiu a assinatura e propagou o argumento em todos os call sites:
- `get_level_config` (boss level, fixed levels, force_meteor_storm, procedural)

### 2. Level 1 corrigido
- `enemies_to_clear` estava como `1` → corrigido para `75`
- `boss_type=StoneGolemBoss` estava acidentalmente no nível 1 → removido

### 3. Sistema de variety cap adicionado
`_apply_enemy_variety_cap` + `MAX_ENEMY_VARIETY_BY_DIFFICULTY` + `THEME_BASE_ENEMY` são uma adição
sólida — limita a variedade de inimigos simultâneos e garante que o inimigo base do tema sempre
tenha um slot reservado. O design é correto.

### 4. Bloco de progressão por estágio (STARFIELD/CITY/VOLCANIC/PROCEDURAL)
A intenção é boa — usar bandas hardcoded de stage_progress ao invés da função genérica de pesos,
oferecendo maior controle sobre a curva de spawn.

## Problemas encontrados nos novos ajustes

### BUG 1 — `hash()` não-determinístico em `_apply_enemy_variety_cap` [P3]

**Arquivo:** `game/core/levels.py:608`

```python
rng = random.Random(config.level_number * 7919 + hash(world.theme.value))
```

`hash()` de strings é randomizado por PYTHONHASHSEED desde Python 3.3. Dois runs do jogo com o
mesmo nível podem gerar pools de inimigos diferentes, quebrando a garantia de determinismo.

**Fix:**
```python
import zlib
theme_seed = zlib.adler32(world.theme.value.encode())
rng = random.Random(config.level_number * 7919 + theme_seed)
```

---

### BUG 2 — Primeiro bloco de `generate_config` é computação morta para temas não-MOUNTAINS [P1]

**Arquivo:** `game/core/levels.py:1387–1428` vs `1482–1523`

O bloco genérico (linhas 1387–1428) calcula `Alien`, `EyeEnemy`, e `SquareMinionBoss` com
`_get_progressive_enemy_weight`. Imediatamente depois, para STARFIELD/CITY/VOLCANIC/PROCEDURAL
(linhas 1482–1523 — novo código), esses mesmos três inimigos são sobrescritos com valores fixos.

Resultado:
- A computação do Bloco 1 (com progressive weights) é descartada.
- Só o `Meteor` vem do Bloco 1 para esses temas.
- Os dois blocos são inconsistentes: Bloco 1 usa `_get_progressive_enemy_weight`, Bloco 2 usa
  bandas hardcoded de `stage_progress`.

**Fix:** Extrair o Bloco 2 para ser a única fonte de verdade para esses temas, removendo o
cálculo redundante do Bloco 1 para Alien/EyeEnemy/SquareMinionBoss quando o tema não é MOUNTAINS.
Adicionar uma guarda no início do bloco genérico:

```python
is_space_theme = world.theme in (
    WorldTheme.STARFIELD, WorldTheme.CITY, WorldTheme.VOLCANIC, WorldTheme.PROCEDURAL
)

# Aliens (nível 2+) — apenas para MOUNTAINS; temas espaciais usam bloco dedicado abaixo
if level_number >= 2 and not is_space_theme:
    ...  # bloco genérico existente

# Eyes (nível 5+)
if level_number >= 5 and not is_space_theme:
    ...

# SquareMinionBoss (nível 3+)
if level_number >= 3 and not is_space_theme:
    ...

# ...depois o bloco dedicado para temas espaciais mantido como está
```

## Bugs pré-existentes que ainda precisam ser corrigidos

### P0 — Timers de mine/propeller/formation usam `1/60` hardcoded

**Arquivo:** `game/systems/spawner.py:967, 1004, 1022`

A frequência de minas, propellers e formações é frame-rate dependente. A 120 FPS, esses timers
correm 2x mais rápido que o esperado. Existem inclusive TODOs no próprio código.

**Fix:** Passar `dt` para os três métodos, mudando a assinatura:

```python
# Antes
def _update_mine_spawner(self, entity_manager: "EntityManager") -> None:
    self.mine_spawn_timer.update(1 / 60)

# Depois
def _update_mine_spawner(self, dt: float, entity_manager: "EntityManager") -> None:
    self.mine_spawn_timer.update(dt)
```

E ajustar as chamadas em `update()`:
```python
self._update_mine_spawner(dt, entity_manager)
self._update_propeller_spawner(dt, entity_manager)
self._update_formation_spawner(dt, entity_manager)
```

### P0 — `spawn_rate_multiplier` do WorldConfig aplicado duas vezes

**Arquivo:** `game/core/levels.py:1327–1332` + `game/core/levels.py:1815–1818`

Em `generate_config`, o multiplicador é aplicado via `world_spawn_mult`:
```python
world_spawn_mult = float(world.theme_modifiers.get("spawn_rate_multiplier", 1.0))
spawn_multiplier = theme_spawn_mult * preset_spawn_mult * world_spawn_mult
```

Depois `_apply_world_theme_to_config` aplica novamente:
```python
spawn_rate_mult = world.theme_modifiers.get("spawn_rate_multiplier", 1.0)
adjusted_spawn_config[enemy_type] /= spawn_rate_mult
```

Para o World 4 (VOLCANIC, `spawn_rate_multiplier: 1.15`), o spawn é dividido por `1.15²=1.3225`
ao invés de `1.15`.

**Fix (opção A — remover de `generate_config`):**
```python
# Remover world_spawn_mult do generate_config — deixar _apply_world_theme_to_config como única fonte
spawn_multiplier = theme_spawn_mult * preset_spawn_mult  # sem world_spawn_mult
```

**Fix (opção B — remover de `_apply_world_theme_to_config`):**
Remover o bloco `spawn_rate_mult` de `_apply_world_theme_to_config`, mantendo apenas
`meteor_weight`, `alien_weight` e `eye_weight`.

Opção A é preferível pois `_apply_world_theme_to_config` é o lugar natural para aplicar
modificadores de WorldConfig.

### P2 — `_count_enemies_by_type` chamado 3x por frame

**Arquivo:** `game/systems/spawner.py` — método `update()`

Por frame: `_refresh_death_clocks`, `_record_pressure_sample`, e `_get_dynamic_enemy_weights`
chamam `_count_enemies_by_type` independentemente.

**Fix:** Calcular uma vez por tick:
```python
def update(self, dt, entity_manager, ...) -> None:
    self.spawn_clock += dt
    counts = self._count_enemies_by_type(entity_manager)
    self._refresh_death_clocks(counts)
    if self.use_weighted_spawn:
        self._record_pressure_sample_from_counts(counts)
        self._update_weighted_enemy_spawn(..., precomputed_counts=counts)
```

def _is_storm_level(self) -> bool:
