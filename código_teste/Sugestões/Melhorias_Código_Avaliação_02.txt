# Code Review: Event Bus Implementation

Resumo executivo do estado do Event Bus: O sistema está totalmente integrado, reativo e agora permite customização visual via eventos.

---

## Corrigido

### 1. Duplicação de explosões
O handler legado de `EnemyDestroyed` foi removido de `EffectsSystem`. Agora as explosões são geridas centralizadamente via `EntityManager` (para mortes diretas) ou via evento `SpawnEffect`, eliminando o efeito visual duplo.

### 2. SoundSystem e Métodos do Gerenciador
O `SoundSystem` foi atualizado para utilizar exclusivamente os métodos expostos pelo `sound_manager` (ex: `play_shot`, `play_explosion_boss`), garantindo consistência sonora.

### 3. Implementação do método `off()`
O `EventBus` agora possui suporte completo para remoção de handlers, e todos os sistemas reativos (`SoundSystem`, `EffectsSystem`) utilizam o `off()` em seus métodos `cleanup()`, prevenindo vazamentos de memória e execuções fantasmas.

### 4. Cores customizáveis em Floating Scores
O evento `SpawnFloatingScore` foi atualizado para aceitar um campo opcional `color`. O `EffectsSystem` respeita esse campo, permitindo que a cena decida a cor (ex: Amarelo para combate) sem que o sistema de efeitos precise de lógica de decisão interna.

---

## Pendente / Em Observação

### 1. Baixo consumo de alguns eventos
`LevelCleared`, `ScoreGained` e `GameStateChange` continuam definidos com pouco ou nenhum consumo. A UI ainda lê estados diretamente de `playing.py`.

### 2. Transições de Música
Ainda existem chamadas manuais para troca de música. Migrar os pontos restantes de música/transição para o `EventBus`.
