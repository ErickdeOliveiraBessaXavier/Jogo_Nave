# Revisão Técnica Crítica - Space Shooter

Itens pendentes após implementação do Event Bus e seus refinamentos.

---

## Crítico

### 1. `playing.py` — extração de controladores de domínio (concluída)

`PlayingScene` reunia colisões, progressão de nível, boss fights, upgrades, input, cutscenes, HUD, transições de mundo, cheat codes e meta-progression.

**Extrações realizadas:**
- `BossFightController` (`game/systems/boss_fight_controller.py`) — ciclo de vida do boss, warning system, cleanup de hostis.
- `LevelProgressionController` (`game/systems/level_progression_controller.py`) — thresholds, contagem de hostis, estatísticas da fase, avanço entre níveis, emissão de `LevelCleared`. API por retorno de enum (`ProgressionStatus`), sem callbacks circulares.
- `ShootingSystem` (`game/systems/shooting_system.py`) — cooldown, disparo regular, charge shots do Magneto/Caçador e canal de áudio do laser carregado.

`PlayingScene` ficou reduzida de ~3150 para ~2800 linhas e os domínios principais agora respondem por sua própria coerência.

## Médio

### 2. `config.py` ainda funciona como namespace global disfarçado

O arquivo concentra configurações de boss, formações, power-ups e UI em um único bloco. Funciona, mas não é uma modelagem saudável para crescimento do projeto.

**Direção recomendada:** separar por domínio.

```python
@dataclass(frozen=True)
class DisplayConfig: ...

@dataclass(frozen=True)
class GameplayConfig: ...

@dataclass(frozen=True)
class GameConfig:
    display: DisplayConfig
    gameplay: GameplayConfig
    bosses: BossConfigs
```
