# Revisão Técnica Crítica - Space Shooter

Resumo executivo dos pontos ainda relevantes após a implementação do Event Bus.

---

## Crítico

### 1. `playing.py` continua concentrando responsabilidades demais

`PlayingScene` ainda reúne colisões, progressão de nível, boss fights, upgrades, input, cutscenes, HUD, transições de mundo, cheat codes e meta-progression. O risco não é teórico: qualquer mudança em uma área continua com chance de afetar várias outras.

**Impacto:** a cena segue difícil de testar, de manter e de evoluir. O próximo passo natural é extrair controladores de domínio.

**Direção recomendada:**
```python
class BossFightController:
    def start(self, boss_type, health_mult): ...
    def update(self, dt): ...
    def end(self): ...

class LevelProgressionController:
    def check_progression(self): ...
    def advance(self): ...

class ShootingSystem:
    def fire(self, ship, entity_manager): ...
```

### 2. `collisions.py` ainda está fortemente acoplado a tipos concretos

A classe `Collisions` continua conhecendo muitos tipos específicos de entidade e combinações pontuais de comportamento. Isso limita a extensibilidade e aumenta o custo de introduzir novos inimigos ou regras especiais.

**Direção recomendada:** consolidar o fluxo em torno de protocolos como `Damageable` e reduzir métodos específicos por tipo.

```python
class Collisions:
    def projectiles_vs_damageable(
        self,
        projectiles: list[Projectile],
        targets: list[Damageable],
        grid: SpatialGrid,
    ) -> CollisionResult: ...
```

## Médio

### 3. `config.py` ainda funciona como namespace global disfarçado

O arquivo concentra configurações de boss, formações, power-ups e UI em um único bloco. Funciona, mas não é uma modelagem saudável para crescimento do projeto.

**Direção recomendada:** separar por domínio.

```python
@dataclass(frozen=True)
class DisplayConfig: ...

@dataclass(frozen=True)
class GameplayConfig: ...

@dataclass(frozen=True)
class GameConfig:
    display: DisplayConfig
    gameplay: GameplayConfig
    bosses: BossConfigs
```

## Concluído

### 4. O Event Bus foi implementado e integrado

O item de comunicação entre sistemas foi resolvido com eventos tipados e consumidores dedicados.

**Componentes envolvidos:**
- `game/events/game_events.py`: eventos tipados com dataclasses
- `game/core/events.py`: EventBus com `on`, `off`, `emit` e `clear`
- `game/systems/sound_system.py`: áudio reativo a eventos
- `game/systems/effects_system.py`: efeitos visuais reativos a eventos
- `game/app.py`: EventBus centralizado na aplicação
- `game/scenes/playing.py`: emissão de eventos no fluxo de gameplay

**Eventos principais:**
- `PlayerShot`
- `EnemyDestroyed`
- `BossDefeated`
- `PowerupCollected`
- `PlayerDamaged`
- `SpawnFloatingScore`
- `GameOver`

**Antes:**
```python
sound_manager.play_explosion_boss()
self.player_profile.record_clear(...)
self.entity_manager.spawn_explosion(...)
```

**Depois:**
```python
self.app.event_bus.emit(events.BossDefeated(
    boss_type=self._boss_type_cache,
    position=boss_center
))
```
