# Correção: Inimigos não morriam ao sair da tela em side-scroll

## 🐛 Problema Identificado

No modo `side-scroll` (Mountains, City, Volcanic), os inimigos que saíam da tela pela esquerda **não eram contabilizados como mortos**, resultando em:

1. O contador de inimigos destruídos (`enemies_destroyed_in_level`) não avançava
2. A fase só era considerada "passada" após o timer de limpeza de 20 segundos expirar
3. Os inimigos continuavam acumulando em memória mesmo fora da tela

**Por que funcionava no Starfield (top-down) mas não nos outros mundos?**

No Starfield, os inimigos caem pela parte inferior da tela (`enemy.y > screen_height`), e essa verificação funciona. Nos outros mundos (side-scroll), os inimigos vão para a esquerda (`enemy.x < -enemy.w`), mas havia um **bug crítico** na verificação.

## 🔍 Causa Raiz REAL

O arquivo `entity_manager.py` possui a função `_is_enemy_off_screen()`, mas ela tinha **DOIS problemas graves**:

### Problema 1: AttributeError silencioso

A função tentava acessar `enemy.w` diretamente:

```python
def _is_enemy_off_screen(self, enemy: Any) -> bool:
    if self.is_side_scroll:
        return enemy.x < -enemy.w  # ❌ ERRO! enemy.w pode não existir
```

Mas nem todos os inimigos têm o atributo `.w`! Alguns usam `rect.width`. Quando `enemy.w` não existe:
- Python lança `AttributeError`
- A exceção é silenciosamente ignorada ou retorna False
- O inimigo nunca é marcado como fora da tela

**Evidência:** Em outras partes do código, o desenvolvedor usa `getattr(enemy, "w", 0)` com valor padrão, indicando que sabia que `.w` pode não existir!

### Problema 2: Função não era aplicada universalmente

A função `_is_enemy_off_screen()` estava sendo usada **APENAS** para `ExplosiveMine`:

```python
self.enemies = [
    e
    for e in self.enemies
    if not e.dead and not (isinstance(e, ExplosiveMine) and e.is_off_screen())
]
```

Todos os outros tipos de inimigos (meteoros, aliens, eye enemies) **não eram verificados**.

## ✅ Solução Implementada

### Fix 1: Acesso seguro aos atributos de tamanho

Corrigi a função `_is_enemy_off_screen()` para:

1. **Usar `getattr` com fallback** para obter largura/altura
2. **Verificar `rect.width/height`** se `.w/.h` não existir  
3. **Usar valores padrão** (50) como último recurso

```python
def _is_enemy_off_screen(self, enemy: Any) -> bool:
    # Obter largura do inimigo de forma segura
    enemy_width = getattr(enemy, 'w', None)
    if enemy_width is None:
        rect = getattr(enemy, 'rect', None)
        if rect is not None:
            enemy_width = getattr(rect, 'width', 50)
        else:
            enemy_width = 50  # Fallback
    
    # Mesma lógica para altura...
    
    if self.is_side_scroll:
        return enemy.x < -enemy_width  # ✅ Agora funciona!
    else:
        # ... verificações top-down
```

### Fix 2: Aplicar verificação a TODOS os inimigos

Adicionei verificação no método `cleanup()`:

```python
def cleanup(self):
    # Marcar inimigos fora da tela como mortos ANTES de liberar ao pool
    for e in self.enemies:
        if not e.dead and self._is_enemy_off_screen(e):
            e.dead = True
    
    # Resto do cleanup...
```

## 📊 Resultado Esperado

Após aplicar esta correção:

✅ **Starfield (top-down)**: Continua funcionando normalmente  
✅ **Mountains/City/Volcanic (side-scroll)**: Agora funciona corretamente!  
✅ Inimigos que saem da tela são marcados como `dead`  
✅ O contador `enemies_destroyed_in_level` avança  
✅ A fase progride sem esperar os 20 segundos  
✅ Não há acúmulo de inimigos inativos em memória  
✅ Não há mais `AttributeError` ao verificar `.w` inexistente  

## 🔧 Como Aplicar

2. O sistema detectará automaticamente inimigos fora da tela em **ambos os modos**
3. Nenhuma outra alteração é necessária

## 📝 Observações Técnicas

### Por que o bug não aparecia no Starfield?

No modo **top-down**, a primeira verificação é `enemy.y > screen_height`, que funciona **antes** de tentar acessar `enemy.w`. Então mesmo que o acesso a `.w` falhasse, os inimigos já eram removidos pela verificação do `y`.

No modo **side-scroll**, a **única** verificação é `enemy.x < -enemy.w`, que falhava se `.w` não existisse.

### Estrutura dos inimigos

Diferentes inimigos têm diferentes estruturas:
- Alguns têm `.w` e `.h` (width/height)
- Outros têm apenas `.rect.width` e `.rect.height`
- A solução agora suporta ambos os casos

### Performance

- Overhead mínimo: apenas chamadas `getattr` que são muito rápidas
- Verificação ocorre uma vez por frame no `cleanup()`
- Complexidade: O(n) linear nos inimigos ativos
